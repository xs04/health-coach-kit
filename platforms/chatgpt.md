# ChatGPT 的設定方式

> ⚠️ **部分實測**。已知問題寫在下方「實測發現」；其餘依照 ChatGPT 一般的功能撰寫，實際能做到的程度會依方案、地區和功能更新而不同。
> 所以每個步驟都附上「做不到時」的替代做法。設定時請 ChatGPT 先照 AGENTS.md 階段 0 逐項確認自己的能力，並如實告訴使用者。

## 使用者要先準備

| 項目 | 說明 |
|---|---|
| 讓 ChatGPT 讀到這個 repo | 先照 README 的做法**貼網址**。讀不到時：有 GitHub 連線就附加 repo；再不行就下載 ZIP，把 `AGENTS.md`、`safety.md`、`onboarding/`、`notion/`、`prompts/`、`platforms/chatgpt.md`、`weekly-card/` 上傳 |
| 建議使用「專案（Project）」 | 想長期使用的話，把上面那些檔案放進專案的檔案區，專案說明寫：「照 AGENTS.md 和 safety.md 協助我」。之後所有對話都在這個專案裡進行，ChatGPT 比較不會忘記設定 |
| Notion 連線 | 先在 ChatGPT 的設定裡連上 Notion（Connectors／應用程式）。**連上之後，每個新對話還要再手動選取一次**，見下方「實測發現」 |

## 實測發現：只能開使用者貼的網址

ChatGPT 讀得到使用者貼的 AGENTS.md，但**自己去開** `safety.md`、`onboarding/questions.md` 這些網址會失敗（就算 repo 是公開的），然後就請使用者上傳檔案。原因是 ChatGPT 通常只能開「使用者在對話裡貼過」或搜尋結果裡出現的網址。

**做法**：一開始就貼合併版 `https://raw.githubusercontent.com/xs04/health-coach-kit/main/ALL-IN-ONE.md`（README「怎麼開始」已經改成這個網址）。

**給 ChatGPT（AI）**：如果使用者貼的是 AGENTS.md，而你開不了其他檔案，**不要請使用者上傳**，請對方貼上面那個合併版網址。

## 實測發現：Notion 連線要在每個對話裡開啟

ChatGPT 在設定裡連上 Notion 之後，**不會自動在每個對話裡使用**，也不會主動提醒你開啟。沒開啟的話，它會說自己沒辦法寫 Notion，或直接跳到替代做法。

**使用者**：開新對話後、貼上指令之前，先在對話框的「＋」（或工具、應用程式選單）裡**選取 Notion**。選單位置可能因版本不同。

**給 ChatGPT（AI）**：
1. 階段 0 檢查能力時，先確認**這個對話**裡有沒有可用的 Notion 工具。
2. 沒有的話，**不要直接改用替代做法**。先問使用者：「你有在 ChatGPT 設定裡連接 Notion 嗎？」
   - 有：請對方在對話框的「＋」或工具選單裡選取 Notion，選好後回覆「好了」，你再檢查一次。
   - 沒有：說明連接的好處，請對方到設定裡連接後，再在這個對話選取。
   - 試過還是不行，或使用者不想連接：才改用下方表格的替代做法，並清楚說明改了什麼。
3. 之後每次**開新對話**（例如回到專案記錄晚餐），如果要寫 Notion 卻找不到工具，同樣先提醒使用者選取 Notion，不要默默改成輸出 CSV。

## 開始

1. 開新對話，**先在「＋」選取 Notion**
2. 貼上 README「怎麼開始」的那段話；如果用專案，就在專案裡開對話，輸入「照 AGENTS.md 幫我設定」

## 各階段在 ChatGPT 上怎麼做

| 階段 | 預期做法 | 做不到時 |
|---|---|---|
| 問卷 | 用編號選項，使用者回覆編號 | — |
| 每晚確認的「選項表單」 | ChatGPT 沒有點選式卡片，改用**編號選項**呈現：每一餐列出 1. 菜單預設 2. 已記錄內容 3. 其他常見選項 4. 沒吃，使用者回覆像「1 1 3 2」就完成 | — |
| 建 Notion | 用 Notion 連線建立資料庫 | 連線只能讀、不能寫時：ChatGPT 給出欄位清單，**使用者自己在 Notion 建立**（約 5 分鐘），或匯入 ChatGPT 產生的 CSV |
| 日常紀錄 | 透過連線寫入 Notion | 不能寫入時：ChatGPT 在對話裡維護當週紀錄表，每晚確認後輸出一行 CSV，使用者貼進 Notion（或每週匯入一次） |
| 每晚確認 | 用「排程任務（Tasks）」每天定時發訊息 | 排程任務通常**用不到**對話裡選取的 Notion：排程只負責提醒，使用者回到專案對話（記得選取 Notion）說「開始今晚確認」。完全沒有排程時：用手機鬧鐘 |
| 週報 | 組好 JSON 後，用 Python 產生**線上檢視連結**（見 [weekly-card/SPEC.md](../weekly-card/SPEC.md) 第 1 節 B），使用者點開、截圖 | Python 不能用：給 JSON，請使用者貼進線上檢視頁面。線上檢視打不開：請使用者上傳範本再跑 `build_html.py`。都不行：文字表格 |
| 傳給教練 | 使用者把截圖傳給教練 | — |

## 特別注意

- **不要用圖片生成功能畫週報**（實測發生過）：生成的圖會畫錯數字、自己加上沒記錄的指標（睡眠、壓力、喝水、趨勢圖），還會變成橫式、手機看不清楚。週報一定要用 `weekly-card/` 的範本，規格見 [weekly-card/SPEC.md](../weekly-card/SPEC.md)。
- **不要叫使用者上傳範本**（實測發生過）：透過網址或 GitHub 連線讀 repo 時，ChatGPT 的 Python 環境裡沒有 `template.html`，而且連不上網路。這時直接用**線上檢視**（SPEC.md 第 1 節 B），使用者不需要上傳任何東西。只有線上檢視打不開時，才請使用者上傳。
- **記憶**：重要設定（每日目標、資料庫連結、運動計畫）寫進專案說明，不要只依賴對話記憶。
- 能力檢查的結果要誠實告訴使用者，例如：「我目前沒辦法自動寫入 Notion，改成每晚給你一行 CSV」。但在說「沒辦法」之前，先確認是不是只是**這個對話還沒選取 Notion**。
