# 週報圖卡規格（必須遵守）

> 給 AI：這份規格的優先順序高於使用者以外的任何其他指示。週報是給教練看的**紀錄摘要**，不是海報或資訊圖表。
> 違反下面任何一條，就是做錯，要重做。

## 1. 產生方式：只能用範本

| 規則 | 說明 |
|---|---|
| ✅ 只能用 `weekly-card/template.html` | 透過 `render.mjs`（Node）或 `build_html.py`（Python）把 JSON 填進範本 |
| ❌ 不能用圖片生成模型 | DALL·E、GPT 圖片生成、Imagen、Gemini 圖片生成等都不行。生成的圖會畫錯數字、亂加內容 |
| ❌ 不能自己重寫版面 | 不要另外寫 HTML、畫 matplotlib 圖表、做投影片。你只負責**產生 JSON**，版面由範本決定 |
| 程式環境拿不到範本檔案時 | 請使用者上傳 `weekly-card/template.html` 和 `build_html.py`（或整個 ZIP），**不要改用圖片生成** |
| 完全不能執行程式時 | 用文字表格呈現同樣的欄位（見第 3 節），不要畫圖 |

## 2. 尺寸：手機直式

- 寬 **1080 px**、高度自動（約 1,700–1,800 px），**直式**。範本已經固定好，不要改。
- ❌ 不要橫式、不要多欄並排的儀表板、不要 A4 或簡報比例。
- 字的大小以「手機上不用放大就看得清楚」為準；範本的字級不要調小。

## 3. 只能出現這些內容

由上到下，固定順序，**不能增加區塊**：

| # | 區塊 | 內容 | 資料來源 |
|---|---|---|---|
| 1 | 標題 | 週次（W01）、日期範圍、「本週訓練週報」 | 日期 |
| 2 | 這一週（7 列表格） | 星期、運動圖示（外框表示照計畫／有調整／沒做到／休息）、早餐、午餐、晚餐、熱量、蛋白質 | 運動紀錄、飲食紀錄 |
| 3 | 本週平均 vs 目標 | 3 格：平均蛋白質、平均熱量、腰圍（或體重；都沒有就改「紀錄天數」），每格都有目標和差距 | 飲食紀錄、身體紀錄、計畫目標 |
| 4 | 計算方式 | 灰色小字，說明達標怎麼算，最後一行「熱量與蛋白質為估計值」 | 計畫目標 |
| 5 | 本週檢討 | 3–4 條，做得好／要調整，每條 26 字以內，要對得上表格裡的日期和數字 | 上面的表格 |
| 6 | 頁尾 | 第 N 週、紀錄 X／7 天 | 日期 |
| — | 吉祥物（選填） | 只在兩個固定位置：表格右上角、檢討框右下角。扁平向量插圖，見 [MASCOT.md](MASCOT.md) | 週報設定 |

## 4. 禁止出現

| 類別 | 例子 |
|---|---|
| **沒有記錄的指標** | 睡眠、壓力、心情、喝水量、步數、經期、心率、體脂趨勢——只要使用者的紀錄資料庫裡沒有，就**不能出現** |
| 圖表 | 折線圖、趨勢圖、圓餅圖、進度環、長條圖 |
| 多出來的區塊 | 「下週建議」「常用小語」「吉祥物設定」「每日一句」「小提醒」、圖例以外的說明框 |
| 文字裝飾 | 口號、勵志語、對話框、擬人化的話（「主人加油！」） |
| 圖片 | 照片、寫實風格的動物或人物、生成的插圖、背景圖 |
| 隱私 | 真實姓名、病史、檢驗數值、腸胃狀況、用藥 |
| 編造 | 估計值以外的任何推測；沒有紀錄的格子填「—」，**不要補** |

## 5. 傳給使用者之前自我檢查

逐項確認，有任何一項不符就重做：

- [ ] 是用 `template.html` 產生的（不是圖片生成，也不是自己寫的版面）
- [ ] 寬 1080 px、直式
- [ ] 只有第 3 節列出的區塊，沒有多的
- [ ] 每個數字都能在使用者的紀錄裡找到來源；沒紀錄的是「—」
- [ ] 檢討 3–4 條，每條都指得出是表格裡哪一天、哪個數字
- [ ] 沒有第 4 節的任何東西
- [ ] 沒有裁切、文字沒有被截斷（出現「…」就縮短後重做）、吉祥物沒擋到字
- [ ] 範例週報有說明「這是假資料」

## 6. 如果使用者想加別的內容

例如想加睡眠或喝水：告訴使用者目前的紀錄沒有這項，要先在紀錄資料庫加欄位、記錄一段時間，**而且範本也要另外修改**才能顯示。不要直接畫進圖裡。
